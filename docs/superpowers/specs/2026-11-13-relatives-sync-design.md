# CareDose — ญาติ/ผู้ดูแล ซิงก์สองทางระหว่างแอปกับเว็บ Admin

วันที่: 2026-11-13 · ต่อยอดจากเฟส 1–2 (`2026-11-09-admin-integration-design.md`, `2026-11-10-admin-integration-phase2-design.md`) ซึ่งเลื่อน "ญาติ" ไว้
ครอบคลุม 3 ส่วน: ฐานข้อมูล Supabase `eokqjjodfgdpgzievgln` (ไฟล์ `supabase/integration.sql` ในรีโป `caredose-admin`), เว็บ Admin, แอป Flutter

## เป้าหมาย

เป็น Demo ให้คนทดลอง ผู้ใช้ขอสองอย่าง:

1. ญาติที่ผู้ป่วยเพิ่มในแอปต้องไปปรากฏในหน้า "ญาติและผู้ดูแล" ของเว็บ Admin
2. หน้าข้อมูลผู้ป่วยในเว็บต้องแสดงชื่อและเบอร์ของญาติ/ผู้ดูแลที่ผูกกับผู้ป่วยคนนั้น

ผู้ใช้เลือกให้ข้อมูลไหล **สองทาง** คือญาติที่ Admin เพิ่มในเว็บต้องมาโผล่ในรายชื่อญาติบนมือถือด้วย

## ไม่ใช่เป้าหมาย / ต้องไม่เกิดขึ้น

- ผู้ป่วยในแอปไม่สร้างบัญชีผู้ดูแลที่ล็อกอินได้ และไม่ให้สิทธิ์ใครเห็นข้อมูลผู้ป่วย (ญาติจากแอปเป็นเพียงรายชื่อติดต่อ)
- ไม่จับคู่ญาติจากแอปกับบัญชีผู้ดูแลที่มีอยู่แล้วโดยเบอร์โทร เพราะจะทำให้บัญชีนั้นเห็นข้อมูลผู้ป่วยโดยผู้ป่วยไม่ได้ตั้งใจ
- ผู้ป่วยแก้หรือลบได้เฉพาะญาติที่ตัวเองเพิ่ม ไม่แตะแถวที่ Admin สร้าง
- ไม่ทำ: การยืนยันตัวญาติ, แจ้งเตือนญาติ, หน้าแก้ไขญาติแบบใหม่ในเว็บ, ใช้แอปแบบออฟไลน์ล้วนเพิ่มญาติ

## แนวทางที่พิจารณา

- **A (เลือก): ใช้ตาราง `caregivers` + `patient_caregivers` เดิม** ญาติจากแอปเป็นแถว `caregivers` ที่ `user_id` ว่าง และผูกผู้ป่วยผ่าน `patient_caregivers` หน้า "ญาติและผู้ดูแล" ของเว็บอ่านตารางนี้อยู่แล้ว จึงเห็นข้อมูลทันทีโดยไม่ต้องแก้เว็บส่วนนั้น
- B: ตารางใหม่ `patient_relatives` ต้องแก้หน้าเว็บให้รวมสองแหล่ง และมีสองแนวคิดซ้อนกัน จึงไม่เลือก
- ที่ผู้ใช้เลือก: ข้อมูลหลักอยู่บนเซิร์ฟเวอร์ แอปเก็บสำเนาไว้แสดงตอนออฟไลน์

## การออกแบบ

### ฐานข้อมูล (เพิ่มท้าย `integration.sql`, รันซ้ำได้)

- คอลัมน์ใหม่ `caregivers.added_by_patient boolean not null default false` ใช้บอกว่าแถวนี้ผู้ป่วยเพิ่มเอง
- ฟังก์ชัน security definer สามตัว ผู้เรียกต้องเป็นผู้ป่วยที่ผูกกับแถว `patients` (ใช้ `auth.uid()` หา `patients.user_id` ห้ามรับ id ผู้ป่วยจากไคลเอนต์)
  - `list_my_relatives()` คืนญาติทุกคนของผู้ป่วยที่ `patient_caregivers.status <> 'revoked'`: `id` (caregivers.id), `name`, `relationship`, `phone`, `editable`. `editable` เป็นจริงเมื่อ `added_by_patient` เป็นจริง และแถวนั้นผูกกับผู้ป่วยคนนี้คนเดียว
  - `save_my_relative(p_id uuid, p_name text, p_relationship text, p_phone text)` ถ้า `p_id` เป็น null สร้างแถว `caregivers` ใหม่ (`user_id` ว่าง, `added_by_patient` จริง) และแถว `patient_caregivers` (`status = 'confirmed'`, สิทธิ์จัดการแผน/นัดเป็นเท็จ) ถ้ามี `p_id` แก้ได้เฉพาะแถวที่ `editable`
  - `delete_my_relative(p_id uuid)` ลบการผูกกับผู้ป่วยนี้ และลบแถว `caregivers` ด้วยถ้า `editable` และไม่เหลือการผูกอื่น ลบญาติที่ Admin สร้างไม่ได้ (ข้อผิดพลาด 42501)
- ตรวจข้อมูล (ข้อผิดพลาด 22023): ชื่อไม่ว่างและยาวไม่เกิน 100 ตัวอักษร (หลังตัดช่องว่าง), ความสัมพันธ์ไม่เกิน 50, เบอร์ไม่ว่างและไม่เกิน 20, ผู้ป่วยหนึ่งคนมีญาติได้ไม่เกิน 20 คน ผู้เรียกที่ไม่ใช่ผู้ป่วยที่ผูกบัญชีได้ 42501
- เขียน `audit_logs` ในฟังก์ชัน เหมือนฟังก์ชันอื่น (ตาราง `caregivers` กับ `patient_caregivers` ไม่มีทริกเกอร์ audit อยู่แล้ว)
- ไม่ต้องแก้นโยบาย RLS: `cg_r` ให้ Admin/แพทย์อ่าน `caregivers` ได้อยู่แล้ว

### แอป

- โมเดล `Relative` เพิ่ม `editable` (ค่าเริ่มต้นจริง เพื่อข้อมูลเก่าในเครื่อง) ส่วน `id` เปลี่ยนความหมายเป็น id ฝั่งเซิร์ฟเวอร์ (uuid) หลังซิงก์
- ที่เก็บใหม่ `RelativeRepository` (ตัวจริงเรียก RPC สามตัว) และดึงรายชื่อพร้อมรอบ `MedSync.pull` เดิม (ตอนเข้าสู่ระบบ ตอนกลับเข้าแอป และทุก 5 นาที) ผลที่ได้ทับ `AppData.relatives` ที่เป็นสำเนาในเครื่อง
- เพิ่ม/แก้/ลบญาติ ต้องออนไลน์: เรียก RPC ก่อน สำเร็จจึงอัปเดตสำเนา ล้มเหลวแสดงข้อความและไม่แก้สำเนา (ตัดสินใจเอง: ไม่ทำคิวออฟไลน์เพื่อให้เรียบง่าย)
- หน้าญาติ: ปุ่ม แก้ไข/ลบ แสดงเฉพาะญาติที่ `editable` ส่วนญาติที่ Admin สร้างแสดงชื่อ ความสัมพันธ์ เบอร์ และปุ่มโทร แต่ไม่มีปุ่มแก้
- ออกจากระบบแล้วสำเนาถูกล้างตามเดิม (`resetAll`)
- ญาติที่เคยเพิ่มไว้ในเครื่องก่อนอัปเดต (เก็บเฉพาะในเครื่อง): ส่งขึ้นเซิร์ฟเวอร์ครั้งเดียวหลังอัปเดต เมื่อซิงก์สำเร็จ เพื่อไม่ให้รายชื่อเดิมหายเมื่อสำเนาถูกทับ

### เว็บ Admin

- หน้าข้อมูลผู้ป่วย (`PatientDetail`) เพิ่มการ์ด "ญาติ/ผู้ดูแล" แสดง ชื่อ ความสัมพันธ์ เบอร์ ของแถวใน `patient_caregivers` ที่ไม่ถูกเพิกถอน (ต้องดึงชื่อกับเบอร์จาก `caregivers`) ไม่มีปุ่มแก้ ใช้หน้า "ญาติและผู้ดูแล" เดิมสำหรับการแก้
- ถ้าผู้ใช้ไม่มีสิทธิ์อ่านแถว `caregivers` (เช่นผู้ดูแลคนอื่น) แสดงเป็น "-" ไม่ให้หน้าพัง
- หน้า "ญาติและผู้ดูแล" เดิมไม่แก้: ญาติจากแอปแสดงเบอร์และผู้ป่วยที่ผูก ส่วนคอลัมน์สิทธิ์เป็น "ดู" ตามค่า `can_manage_plan` ที่เป็นเท็จ

## สิ่งที่ปล่อยให้ผู้สร้างตัดสินใจ

รูปแบบ JSON ที่ RPC คืน, ชื่อไฟล์เทสต์ SQL (`90_relatives.sql` ตามลำดับเลขเดิม), การเรียงรายชื่อ (ตามเวลาสร้างแล้วตามชื่อ), ข้อความข้อผิดพลาดภาษาไทย

## การทดสอบ

- SQL (PGlite, `pnpm test:sql`): สร้าง/แก้/ลบ, แถวของผู้ป่วยอื่นไม่ถูกเห็นหรือแตะ, Admin สร้างแล้วลบไม่ได้, ไม่ใช่ผู้ป่วยได้ 42501, ตรวจค่าที่ผิดและเพดาน 20 คน, ลบแล้วแถวที่ถูกผูกกับผู้ป่วยคนอื่นไม่หาย, ไม่ไปจับคู่กับบัญชีผู้ดูแลที่มีเบอร์ซ้ำ
- แอป: เทสต์หน่วยของที่เก็บปลอม (ดึง/ทับสำเนา, ล้มเหลวไม่แก้สำเนา, ย้ายข้อมูลเก่าครั้งเดียว, `editable` ซ่อนปุ่ม)
- เว็บ: เทสต์ตัวช่วยจัดรูปรายชื่อญาติ และทดสอบมือ: เพิ่มญาติในแอป → เห็นในเว็บทั้งสองหน้า; เพิ่มญาติในเว็บ → เห็นในแอป
