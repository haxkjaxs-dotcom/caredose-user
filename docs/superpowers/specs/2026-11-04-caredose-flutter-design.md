# CareDose (ยาอุ่นใจ) — Flutter App Design

วันที่: 2026-11-04

## เป้าหมาย

แปลงเว็บแอป CareDose (React, ไฟล์เดียว `src/App.tsx`) เป็นแอปมือถือ Flutter/Dart บน Android และ iOS โดยคงฟีเจอร์และหน้าตาเดิม และเพิ่มการแจ้งเตือนทานยาจริงในเครื่องที่กดตอบจากการแจ้งเตือนได้ ไม่แก้โค้ด React เดิม สร้างโปรเจกต์ใหม่ที่ `caredose_app/`

## ขอบเขต

รวม:
- 4 แท็บ: หน้าหลัก (ยาวันนี้ + แพทย์), BMI, ประวัติ (ปฏิทิน + ส่งออก CSV), ญาติ/นัดหมาย
- หน้าตั้งค่า: ชื่อผู้ใช้, ขนาดตัวอักษร (ปกติ/ใหญ่/ใหญ่มาก), การแจ้งเตือน, ล้างข้อมูล, เกี่ยวกับแอป
- เพิ่ม/แก้ยา, เพิ่ม/แก้/ลบญาติ, โทรหาแพทย์/ญาติ
- แจ้งเตือนทานยาจริง (local notification) พร้อมปุ่มกดตอบ
- ข้อมูลเก็บในเครื่องเท่านั้น

ไม่รวม:
- SMS/OTP จริง (หน้าจอ OTP เป็นจำลองเหมือนเว็บ และระบุในแอปว่าเป็นตัวอย่าง)
- บัญชีผู้ใช้, backend, sync ข้ามเครื่อง
- หน้าต่างแจ้งเตือนเต็มจอ (full-screen intent)

## สถาปัตยกรรม

แนวทาง: Flutter native widgets + `provider` + `shared_preferences`

โครงสร้าง `caredose_app/lib/`:
- `models/` — Med, DoseLog, Doctor, Relative, Appt, BmiRecord, AppData (toJson/fromJson รูปเดียวกับเว็บ)
- `logic/` — `dose_items.dart` (พอร์ต `itemsFor` และสถานะ taken/skipped/pending/missed), `bmi.dart`
- `state/app_state.dart` — `ChangeNotifier` ถือ AppData, บันทึกลง storage ทุกครั้งที่เปลี่ยน, สั่งตั้งแจ้งเตือนใหม่
- `services/storage.dart` — อ่าน/เขียน JSON คีย์ `caredose` ผ่าน `shared_preferences`
- `services/notifications.dart` — ตั้ง/ยกเลิกแจ้งเตือน, จัดการการกดปุ่ม
- `services/csv_export.dart` — สร้าง CSV (UTF-8 BOM) แล้วแชร์ด้วย `share_plus`
- `screens/` — home, bmi, history, contacts, settings
- `widgets/` — card, badge, modal sheet, calendar picker, date range picker, med form, person form
- `theme.dart` — สี teal (brand), ขนาดตัวอักษร, `textScaler`

Packages: `provider`, `shared_preferences`, `flutter_local_notifications`, `timezone`, `flutter_timezone`, `url_launcher`, `share_plus`, `path_provider`, `intl`

## พฤติกรรมหลัก (พอร์ตจากเว็บ)

- รายการยาวันนี้ = ทุกยา × ทุกเวลา ที่อยู่ในช่วง start–end; คีย์ log = `medId|yyyy-MM-dd|HH:mm`
- สถานะ: มี log → taken/skipped; ไม่มี log และเลยเวลา → missed; อื่น ๆ → pending
- เรียงตามเวลา แล้วชื่อยา
- ปุ่ม "ทานทั้งมื้อ" บันทึก taken เฉพาะรายการที่ถึงเวลาแล้วและยังไม่มี log; ย้อนกลับได้ 6 วินาที
- BMI: `น้ำหนัก / (ส่วนสูง/100)²` ปัดทศนิยม 1 ตำแหน่ง; ตรวจน้ำหนัก 0–400 กก., ส่วนสูง 50–250 ซม.; เกณฑ์ <18.5 ต่ำกว่าเกณฑ์, <25 ปกติ, ที่เหลือสูงกว่าเกณฑ์
- ฟอร์มยา: ต้องมีชื่อ, ต้องมีเวลา, วันสิ้นสุดต้องไม่ก่อนวันเริ่ม
- ฟอร์มญาติ: ต้องมีชื่อและเบอร์; ลบต้องยืนยัน
- วันที่แสดงเป็นภาษาไทย ปี พ.ศ.
- ข้อมูลตัวอย่าง (seed) เหมือนเว็บ ใช้เมื่อเปิดครั้งแรก, อ่านข้อมูลไม่ได้, หรือกด "ล้างข้อมูล"

## การแจ้งเตือน

เมื่อ: เปิดแอป และทุกครั้งที่ยา/เวลา/ตั้งค่า/log เปลี่ยน → ยกเลิกของเดิมทั้งหมดแล้วตั้งใหม่

ตั้งอะไร: สำหรับแต่ละยา × เวลา × วัน ในช่วงล่วงหน้า ที่อยู่ในช่วง start–end และยังไม่มี log
- แจ้งเตือนหลักที่เวลายา
- ถ้าเปิด "เตือนซ้ำ" ตั้งเตือนซ้ำ 1 ครั้งที่ +15 นาที
- ข้อความแสดงชื่อยาและขนาด (เฉพาะในเครื่อง; ข้อความ SMS จำลองไม่แสดงชื่อยา)

ช่วงล่วงหน้า: สูงสุด 14 วัน แต่จำกัดให้จำนวนรวมไม่เกิน 60 รายการ (เผื่อเพดาน 64 ของ iOS) โดยนับจากใกล้ไปไกล

ปุ่มบนการแจ้งเตือน:
- **ทานแล้ว** → บันทึก log taken, ยกเลิกเตือนซ้ำของรายการนั้น
- **ยังไม่ทาน** → ปิดการแจ้งเตือนนั้น และยกเลิกเตือนซ้ำ +15 นาทีของรายการนั้น ไม่เตือนซ้ำอีก; ไม่บันทึก log รายการจึงเป็น "รอทาน" แล้วกลายเป็น "เลยเวลา" เมื่อเวลาผ่านไป (ยังกด ทานแล้ว/ข้ามยา ในแอปทีหลังได้); แจ้งเตือนรอบยาถัดไปทำงานตามปกติ
- **ข้ามยา** → บันทึก log skipped, ยกเลิกเตือนที่เหลือของรายการนั้น

การกดปุ่มขณะแอปปิดอยู่: handler ระดับ top-level (`@pragma('vm:entry-point')`) เขียน log ลง `shared_preferences` โดยตรง; เมื่อเปิดแอปครั้งถัดไปโหลด log ใหม่และตั้งแจ้งเตือนใหม่

Android: channel ความสำคัญสูง (heads-up); ขอ `POST_NOTIFICATIONS` (13+) และ exact alarm; ถ้าไม่ได้สิทธิ์ ใช้ inexact และแสดงคำเตือนในหน้าตั้งค่า
iOS: ปุ่มอยู่ใน notification category (กดค้าง/ดึงลงเพื่อเห็น); ขอสิทธิ์ alert/sound/badge

การตั้งค่า "เปิดการแจ้งเตือน" ปิด → ยกเลิกทั้งหมด. ช่องทาง "ผ่านแอป/SMS/ทั้งสอง" เป็นค่าตั้งเท่านั้น; จริง ๆ ส่งเฉพาะผ่านแอป ส่วน SMS ระบุว่าเป็นตัวอย่าง

## ข้อผิดพลาด

- JSON เสีย/อ่านไม่ได้ → ใช้ข้อมูลตัวอย่าง ไม่ crash
- ไม่ได้สิทธิ์แจ้งเตือน → แบนเนอร์คำเตือนในหน้าตั้งค่า พร้อมปุ่มเปิดการตั้งค่าระบบ
- โทรไม่ได้ (`tel:` เปิดไม่ได้) → แสดง snackbar
- ส่งออก CSV ล้มเหลว → snackbar

## การทดสอบ

- Unit: `dose_items` (ช่วง start–end, สถานะ, การเรียง), BMI (ค่าและเกณฑ์, ขอบเขต), CSV (escape เครื่องหมายคำพูด, BOM), JSON roundtrip ของ AppData, ตัวคำนวณตารางแจ้งเตือน (จำกัด 60 รายการ, ข้ามรายการที่มี log, เตือนซ้ำ)
- Widget smoke test: เปิดแอป, สลับ 4 แท็บ, กด ทานแล้ว บนหน้าหลัก
- ยืนยันบนอุปกรณ์/emulator: แจ้งเตือนเด้งพร้อมปุ่ม, กดปุ่มแล้ว log เปลี่ยนแม้แอปปิด (ไม่สามารถทดสอบอัตโนมัติได้)
